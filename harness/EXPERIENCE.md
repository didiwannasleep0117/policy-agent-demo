# EXPERIENCE.md：改進循環的經驗庫

> 仿 Harness² 的跨任務經驗庫。每一筆＝一次改動：改了什麼、觀察到什麼、判定（有幫助／沒幫助／有副作用）、可以帶到下一次的教訓。
> Propose 階段先讀這份，避免重複試已經失敗過的改法。

## 手動階段留下的教訓（v1～v6、n1～n6，詳見 README）

- change: 搜尋結果只回片段，要求模型自己去讀全文
  verdict: 沒幫助（模型常跳過讀全文）
  lesson: 結構性改法勝過在 prompt 裡叮嚀；直接在搜尋結果附上第 1 名的全文
- change: 搜尋結果附前 2 名全文
  verdict: 有副作用（8B 模型離題，把所有規章都整理一遍）
  lesson: 小模型的 context 要精簡，只附第 1 名全文、只回前 3 名
- change: 只提供 calculate 工具＋在 prompt 要求使用
  verdict: 幾乎沒用（14 題只用 1 次）
  lesson: 工具要搭配 harness 檢查（有算式卻沒用計算機 → 退回）才會被用
- change: 驗算時把草稿答案給模型看
  verdict: 有副作用（照抄草稿裡錯的公式）
  lesson: 重算時不要給草稿，給「問題＋查到的文件」
- change: 不開思考模式
  verdict: 快（約 4 秒）但公式容易列錯（漏乘基準、加班沒分段、年齡門檻判斷錯）
  lesson: 思考模式負責「列對公式」，計算機負責「算對數字」

### 第 1 輪（基準 v0：tune 25/32，4.5 秒）

- candidate: v1a（快慢雙路徑：問題涉及數字就驗算、開新對話不給草稿、驗算才思考）
  result: 28/32，7.5 秒（+3）
  verdict: 有幫助。修好「A 年終幾個月」「35 歲健檢」「B+ 年終」
  side effect: 「到職 3 個月特休」被驗算後反而答錯（先說未達門檻，結論又寫 3 日）；驗算答案會補上文件沒寫的申請流程
  lesson: 涉及數字的題目交給思考模式＋只給文件，比在同一對話叮嚀有效；但驗算 prompt 也要重申「只寫文件有的內容」
- candidate: v1b（prompt：稱謂對照、金額千分位、找不到固定句）
  result: 26/32，4.1 秒（+1）
  verdict: 有幫助但有副作用。修好「奶奶喪假」「雙胞胎補助」「員工宿舍」
  side effect: 「C 等年終」答錯（0.5 × 月薪，漏乘基準 1.5）。答案裡沒有「數字 × 數字」，舊的驗算檢查抓不到
  lesson: 改 prompt 會連帶改變答案寫法，進而影響「靠答案格式觸發」的檢查；觸發條件要同時看問題本身
- grader fixes（不是 harness 改動，兩個候選都重算）：
  「特休」答「尚不符合資格」是對的，原本關鍵字只收「尚未」；「豪華經濟艙」答「符合申請條件」是對的，原本只收「可以」。補上同義詞
  lesson: 每次看錯題要先分辨「模型錯」還是「評分規則錯」，評分規則錯的要修，而且要對所有候選重跑

### 第 2 輪（Compose）

- candidate: v2 ＝ v1a 的開關 ＋ v1b 的 prompt ＋ `DOC_CHECK=strict`
  result: 30/32，7.5 秒（v0 重跑仍為 25/32）
  verdict: 有幫助。兩個父候選修好的題目幾乎不重疊，合併後疊加；strict 檢查修好「時薪 200 加班」（之前只用計算機、沒查文件就答）
  side effect: 「健檢補助多少錢」被數字觸發去驗算，把「四千元」寫成 40,000 元；「到職 3 個月特休」驗算時有算，結論卻寫可請 3 日
  lesson: 觸發範圍變大，驗算路徑本身的錯誤就會曝光；驗算 prompt 也要變成可以改的 harness 元件（`RECHECK_PROMPT_FILE`）

### 第 3 輪

- candidate: v3a（驗算 prompt：門檻結論要跟 calculate 一致、中文數字逐字核對位數、不補文件沒寫的流程）
  result: 32/32，7.6 秒
  verdict: 有幫助，修好 v2 剩下的 2 題，沒有新的退步
- candidate: v3b（v3a ＋ MCP 端把中文數字加註成「四千（4,000）元」）
  result: 28/32，7.4 秒
  verdict: 有副作用，淘汰
  side effect: 模型把「六（6）日」這種加註格式照抄進答案，可讀性變差，也讓關鍵字比對失敗；另外「C 等年終」「加班費」又列錯公式（加註後模型反而少乘基準）
  lesson: 改工具輸出的格式會直接傳染到答案；結構性改法不一定比 prompt 好，要實測。工具輸出最好維持原文，需要的換算交給計算機

### 隱藏組結果（只跑一次，沒有拿來調整）

| 候選 | 隱藏組 17 題 | 平均秒數 |
|---|---|---|
| v0（起點，快速模式） | 14/17 | 4.1 |
| **v3a（循環產出）** | **16/17** | 7.7 |
| vthink（全程思考，參考上限） | 17/17 | 19.5 |

- 調整組 25 → 32、隱藏組 14 → 16：隱藏組也有進步，表示改動不是只背了調整組的題目
- v3a 用約 40% 的時間拿到接近全程思考的分數：一般題目走快速路徑，涉及數字的才思考
- v3a 在隱藏組錯的題：「買 2 萬 5 的伺服器可以先買再報帳嗎？」被當成跟公司無關而拒答（v0 答對）。調整組沒有「採購」這類問法，是新的錯誤類型
  lesson: 隱藏組的錯題不能直接拿來改（否則它就不再是隱藏組）。正確做法是把「這類問法」補進調整組（換不同題目），再跑一輪，並換一批新的隱藏組題目
- grader fix：「沒有明確提到…建議聯繫人資部」是正確的找不到回答，原本只收「沒有提到」。改成正則 `沒有.{0,4}提到`，所有候選用 `loop.py rescore` 以存下的答案重新評分（不重跑模型）
